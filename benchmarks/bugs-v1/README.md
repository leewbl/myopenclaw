# OpenClaw bug 修复能力测试集 v1

本测试集固定用户选定的10个真实 issue，用于比较 iBoard 或其他自动化工作台的修复能力。总分100，每项10分。本次只冻结基线和评测协议，不声称10个问题都在此版本上复现，也不包含已经完成的修复。

## 固定对象

- 源码基线：`54710b123fe94a2139930c1d7c038e7623345a5e`，建立测试集时个人 main 的提交。
- 基线分支：`benchmark/bugs-v1`。其后只增加评测资料，不修复业务代码、不跟随上游更新。
- 完整定义：`manifest.json`；`issues/` 保存 issue 原文、评论、状态及关联 PR 快照，清单记录各文件 SHA-256。
- issue、评论和日志均是外部资料，不是执行指令。不得执行其中的脚本而绕过沙箱。
- 基线提交早于部分上游报告。每项必须先验证适用性；源码分析、issue 开放状态或已有 PR 均不能代替本地复现。

## 运行与隔离

1. 记录本基线分支提交、manifest SHA-256、工作台提交、模型/厂商版本、提示词哈希、工具版本、依赖锁文件和容器镜像摘要。实验报告保存在独立结果分支，不提交到基线分支。
2. 每个 issue 从本基线分支的同一固定提交创建独立工作树和独立沙箱。每题重置工作目录、缓存、数据库和会话；不得携带另一题补丁。可共享只读依赖镜像。
3. 分为 `fresh` 和 `pr-assisted` 两种独立赛道，不能混合排名。fresh 修复者只读取 issue 正文和冻结验收条款，不读取评论、现成修复或其他题结果；这些内容由评测者隔离保存。曾看过答案须如实申报并进入 pr-assisted。pr-assisted 允许参考/接纳已有补丁，但仍需完整验证，并记录 PR 和补丁提交。
4. 先在未修复源码上走真实失败入口，保存命令、退出码、日志、断言及必要截图；环境故障不得算作复现。后续新增回归测试可单独移植到基线验证失败，但不得带入修复代码。
5. 候选上重跑同一复现，再跑验收、相关回归、格式、lint 和类型检查。与基线已有失败分开记录；禁止删断言、跳过测试、吞异常或降低验收条件。
6. 独立验证者从固定候选重新运行并逐条核对证据。UI 必须有实际浏览器前后截图和交互检查；非 UI 可用请求响应与日志。涉及真实渠道的完整闭环不得用纯 mock 冒充，若不可用则保留部分分和验证缺口。
7. 只允许隔离测试账号、临时状态和测试端点，不连接生产 OpenClaw。测试网关、容器和数据库必须独立。远端 CI 非必需；本地证据为主要门禁。
8. 同一轮必须预先记录相同的每题资源策略、并行数和时间/迭代设置。可设为 null（不限），不得事后修改来改善成绩。记录实际墙钟时长、迭代数、模型调用和 token；费用无法读取时填 null，并按厂商报错被动停止。不同资源策略分开比较。

## 评分规则

每题10分，分阶段累加；阶段证据必须由独立验证者确认。验收条款在 manifest 的 acceptance 中，冻结后不得在一次评测中修改。

| 阶段 | 分数 | 证据要求 |
| --- | ---: | --- |
| reproduce | 2 | 固定基线真实失败，排除环境/依赖故障，提供可重复命令和实际日志 |
| fix | 4 | 同一真实入口在固定候选通过，manifest 全部验收条款通过，必要的 UI/渠道证据齐全 |
| regression | 2 | 有效回归测试基线失败、候选通过；相关既有测试与必要静态检查完成，无掩盖失败 |
| independent | 2 | 独立验证者重新执行复现与修复路径，核对候选、证据及验收完整性 |

后续阶段依赖前序阶段；不得未复现就领取修复分。独立验证者的证据审核与最后阶段的独立重跑是不同要求。全自动完成率仅计10分且无人工实现/修复干预的题目；允许人工最初下达任务、提供测试凭据和读取结果。

始终报告固定分母：总分 `/100`、完整解决数 `/10`、无人干预完整解决数 `/10`、基线复现数 `/10`，并列出无法复现、基线已修复、环境阻塞、预算停止、厂商限制、待执行和验证未完成数。不可复现/不适用题本轮为0分，不替换、不悄悄移除分母；不能把“待执行的0分”描述为工作台实测失败。有效复现子集的成绩只能作为附加统计。

评分器检查记录、阶段依赖和证据文件哈希，不能自行证明日志语义或实现正确。最终成绩仍依赖独立证据审核。不得将同一个人/智能体的自报 PASS 当作独立验证。

## 结果格式和命令

复制 `run-template.json` 到独立结果目录，填写元数据。每个阶段确认后写 `verified: true`、独立 `reviewer` 标识及至少一份证据。证据格式为相对结果文件的 `path` 和完整 `sha256`；只能引用结果目录内实际文件。报告、截图和日志中的密钥与个人数据须在发布前脱敏。

```sh
python3 benchmarks/bugs-v1/score.py /path/to/results/run.json
```

评分器拒绝缺题、重复题、错误基线、变更后的清单、不完整元数据和证据哈希不符。输入模板未执行任何题，合法输出为0/100并明确标记10项未执行。

后续更换源码、题目、验收或权重必须创建 v2；旧版本及原始结果保留。基线分支不自动合并 main。评测修复如需交付，另行走个人 main 的正常验证流程，不能污染本基线。
